The AI Timeline Pyramid

Artificial intelligence did not appear overnight. It grew from ancient questions about thinking machines, through the rule-based programs of the 1950s to the 1980s and two winters of lost funding, to the data-driven revolution in machine learning and, finally, the generative models and large language models that many people now use every day. This pyramid stacks that story in layers: the wide base is the groundwork, each narrower layer is a more specialised and more capable stage, and the apex looks at what comes next. Select any event to see what happened, why it mattered and how it changed industry and daily life.

        Design plan

        The five planning decisions for the pyramid architecture. Each one is applied to the live page above: use the design view controls to see it.

        1. Layers

        Six layers, from the base up. The brief suggests five; machine learning and deep learning are split so that no layer holds more than one row of tiles. Layers group events by how the technology gets its ability, so they overlap a little in time.

        LayerNameWidthEvents (numbers from the brief)
        • Which layer? Rules, logic or search: layer 2. Learns from data: layer 3. Deep networks at scale: layer 4. Creates new content: layer 5. Ideas before working machines: layer 1. Speculation: layer 6.
        • Order inside a layer. Left to right by date. Ranges and eras such as 2004 to 2007 sit at their start year.
        • When a layer is full. Extra tiles wrap to a second centred row. Width never changes, so adding events never changes the shape.

        2. Visual narrative

        • Width is accumulated groundwork. The base is 100 percent and each layer above is 12 points narrower, down to 40 percent at the apex.
        • Tone is depth. Fills run from deep slate at the base to pale blue at the apex, like strata of rock.
        • A coloured edge is the subfield. The subfield name is always printed too, so colour is never the only clue.
        • Time reads upward. Turn on Connectors to thread every event in date order. The zigzag shows how the layers overlap in time.
        • Events never move. Search and filters dim tiles, so people keep their sense of the whole shape.

        3. Tooling

        Chosen: an interactive HTML page (this page: HTML, CSS and plain JavaScript, with no framework or build step).

        Why: it is the only option on the list that gives full control over the pyramid’s shape, real buttons for every event, search and filtering, keyboard and screen-reader access, a layout that adapts to phones, and a free shareable link through GitHub Pages.

        • Canva: quick, but the layout is template-bound and detail views are separate pages.
        • Prezi: zooming hides the overview the pyramid exists to show.
        • Figma: excellent for sketches, but a prototype is not a real page with keyboard and screen-reader support.
        • Slides with links: a fallback if nobody can code.

        4. Interactivity

        • Select a tile (click, tap, Enter or Space) to open its detail card with the four-part note.
        • Move between events with Previous and Next, or the Left and Right arrow keys.
        • Close with the button, Escape or a tap outside. Focus returns to the tile.
        • Search and subfield pills dim non-matching tiles and combine with each other.
        • Share a link such as index.html#m16 to open an event directly.
        • Where the detail appears: a centred card on desktop, a bottom sheet on phones. Turn on Annotations, then open any event, to see each part of the card labelled.

        5. Layout grid

        • Desktop: 12 columns, 24 px gutters, container up to 1120 px. Turn on Grid overlay to see them.
        • Layers: 16 px padding, 6 px gaps, 14 px corner radius. Widths of 100, 88, 76, 64, 52 and 40 percent.
        • Tiles: flexible between 150 and 210 px (about 172 px at full width) with 8 px gaps and a 6 px subfield edge.
        • Phones (under 760 px): 4 columns. Layers step in 16 px per level to keep the pyramid silhouette, and the card becomes a bottom sheet.
        • Very small phones (under 420 px): tiles go full width, one per row.
        • Connecting lines: a dashed amber thread joins events in date order, drawn between the layer fills and the tiles.

          Event data lives in data.js. Notes are draft copy standing in for the Tier 3 writing. Dates marked as ranges or eras are shown as written in the course brief.
